# FitGuide v2 Design Brief：从动作字典到训练助手

Date: 2026-07-31
Status: Draft
Baseline: FitGuide v1.0

## 1. 一句话定义

FitGuide v2 在保留“离线、中英对照、冷静沉浸”的动作字典体验之上，补齐一次真实训练的完整闭环：

> 选择计划 → 开始训练 → 逐组记录 → 休息计时 → 完成总结 → 回看历史。

v2 不追求成为课程、社区或健康平台。它仍然是一款可以在健身房现场快速打开、安静使用、无需账户和网络的个人训练工具。

## 2. v1 基线与核心问题

v1 已经完成：

- 1324 个动作离线浏览与中英双语展示
- 动作名、部位、器械、目标肌群搜索与筛选
- 收藏、最近浏览与自定义收藏夹
- 训练计划、组数/次数设置和组完成圆点
- 分享、设置、版权与无障碍基础能力

但 v1 的训练计划更接近“可勾选清单”，还不能可靠表达一次训练：

- 计划模板和完成状态混在 `TrainingPlanItem` 中，完成一次会改变模板自身
- 没有重量、实际次数、训练时间或休息时间
- 没有独立的训练 Session，也就没有可信的训练历史
- 训练过程中需要频繁返回计划列表或动作详情，缺少连续流程
- 完成后没有摘要，用户无法知道本次做了什么

## 3. v2 产品目标

### G1：完成一次训练

用户从一个计划开始，能连续完成所有动作和组，过程无需离开训练模式。

### G2：保存可信记录

计划是可重复使用的模板；每次执行生成独立记录，包含实际组数、次数、重量和时间。

### G3：降低现场操作成本

主要交互适合单手、短暂查看和快速录入。完成一组应在一次点击内完成，修改数据不超过两次点击。

### G4：保留 v1 气质和约束

- 中英双语始终并列
- 默认深色深空背景与克制的 Liquid Glass
- 所有数据仅本机保存
- Gym visual 版权页脚与测试不可移除
- 不引入账户、订阅、社交或联网依赖

## 4. 成功标准

v2.0 达成以下条件才算完成：

- 用户可从任意非空计划开始一次训练
- 计划模板不会因训练完成而被修改
- 每个训练组可记录实际次数和可选重量
- 完成组后可自动启动可配置休息计时器
- App 被切到后台或意外退出后，可以恢复未完成训练
- 用户可结束或放弃训练，二者在历史中有明确区别
- 完训摘要正确展示时长、动作数、完成组数和总训练量
- 历史列表与详情能准确还原一次已完成训练
- v1 收藏数据在升级后安全保留但不再展示；计划和最近浏览继续可用
- AttributionTests、数据模型测试、训练统计测试和关键 UI 流程测试通过

### 建议体验指标

- 从训练 Tab 到开始第一组：不超过 3 次点击
- 完成一组：1 次点击
- 修改重量或次数：不超过 2 次点击
- 冷启动恢复进行中训练：进入 App 后 2 次点击内可继续
- 训练记录保存：完成组后立即持久化，不依赖结束训练按钮

## 5. 目标用户与主要场景

### 核心用户

已经会使用基础健身器械，但仍需要动作参考和简单记录的健身新手或初级训练者。

### 核心场景

1. 用户在训练前创建或选择一个计划。
2. 到达健身房后点击“开始训练”。
3. 查看当前动作、计划次数和可选 GIF。
4. 输入本组重量与实际次数，点击完成。
5. 在休息计时结束后进入下一组或下一动作。
6. 完成训练并查看摘要。
7. 之后从历史记录回看训练内容。

## 6. 信息架构

使用三个 Tab，移除低价值收藏入口：

1. **动作 Exercises**
   - 动作浏览
   - 搜索与筛选
   - 动作详情
   - 加入计划

2. **训练 Training**
   - 进行中的训练（存在时置顶）
   - 快速开始
   - 训练计划
   - 最近训练
   - 训练历史

3. **我的 Profile**
   - 设置
   - 关于
   - 数据说明与版权

训练期间采用独立的全屏 `WorkoutSessionView`，避免底部 Tab 导航造成误触。用户主动退出时，训练仍保持进行中并可从训练 Tab 恢复。

## 7. v2.0 核心功能

### 7.1 训练首页

训练 Tab 从单纯的计划列表升级为训练入口：

- 若存在进行中训练，顶部显示“继续训练”卡片
- “快速开始”可创建一个空白训练并临时添加动作
- 展示训练计划列表，每个计划提供“编辑”和“开始”入口
- 展示最近 3 次已完成训练
- 提供完整历史入口

空计划不可开始训练，但可继续编辑。

### 7.2 开始训练

从计划开始时，将当前计划复制成训练快照：

- 保存计划 ID 和计划名称快照
- 按计划顺序创建 `WorkoutExercise`
- 按计划组数创建 `SetLog`
- 保存计划次数作为每组目标次数
- 后续修改计划不会影响已经开始或已经完成的训练

同一时间只允许一个 `active` 训练。若用户尝试开始另一训练，应先提示继续或结束当前训练。

### 7.3 训练模式

训练模式的视觉优先级：

1. 当前动作中文名与英文名
2. 当前组 / 总组数
3. 重量与实际次数
4. 完成组按钮
5. GIF 与动作步骤快捷入口
6. 上一个 / 下一个动作

核心行为：

- 默认沿用上一组重量
- 实际次数默认使用目标次数
- 重量允许为空；为空时不计入训练量
- 完成组后立即保存
- 用户可撤销已完成组并修正重量或次数
- 用户可跳过动作、临时添加动作或删除尚未完成的临时动作
- 结束训练前展示未完成组提示，但允许用户确认结束

### 7.4 休息计时器

- 默认休息时间为 90 秒
- 设置范围建议 30–300 秒
- 完成组后自动开始，可在设置中关闭
- 支持 `+15s`、跳过和暂停
- 退到后台后以目标结束时间计算剩余时间，避免 Timer 漂移
- 计时结束使用声音或触觉提醒，尊重系统静音与通知权限
- 进行中的训练在支持的 iPhone 上显示为锁屏实时活动与灵动岛，展示当前动作、组进度和休息倒计时

### 7.5 完训摘要

完成训练后展示：

- 计划名称或“自由训练”
- 开始、结束时间与总时长
- 完成动作数
- 完成组数 / 计划组数
- 总次数
- 总训练量：`Σ(weightKg × actualReps)`，忽略未填写重量的组
- 每个动作的完成明细

摘要数据必须从持久化的 `SetLog` 计算，不保存可漂移的重复汇总字段。

### 7.6 训练历史

- 按日期倒序显示已完成训练
- 进行中和放弃的训练不混入“已完成”默认列表
- 历史详情只读，展示当时的动作和组数据快照
- 删除历史需要二次确认
- v2.0 不提供图表、周报或复杂趋势分析

### 7.7 快速开始

自由训练不要求先创建计划：

- 创建空的 `WorkoutSession`
- 从动作库搜索并添加动作
- 每个动作默认 3 组 × 12 次，可在训练中修改
- 完成后作为普通训练历史保存
- 可在完训页选择“另存为计划”，此项可延后至 v2.1

## 8. 搜索与动作发现增强

搜索增强属于 v2.1，不阻塞 v2.0 训练闭环：

- 统一标准化大小写、空白和重音符号
- 支持中文拼音搜索
- 新增本地别名表，例如“卧推”“bench press”等常用称呼
- 搜索与筛选可组合，而不是互相替代
- 动作详情提供“相似/替代动作”

替代动作使用确定性本地规则：

1. 优先相同 `target`
2. 再匹配相同 `bodyPart` 或 `muscleGroup`
3. 优先展示不同 `equipment`
4. 排除当前动作并稳定排序

“新手友好”“难度”“常见错误”等标签在当前数据集中没有可靠字段，不能根据名称自动猜测。只有在增加人工审核的数据覆盖层后才能展示。

## 9. 经审核的动作指导覆盖层

属于 v2.2，独立于 Gym visual 原始数据保存：

```text
exercise-guidance.json
└── exerciseId
    ├── cues.zh / cues.en
    ├── commonMistakes.zh / commonMistakes.en
    ├── difficulty
    ├── aliases.zh / aliases.en
    ├── reviewedAt
    └── sourceNote
```

约束：

- 不修改或覆盖原始 Gym visual 数据与 attribution
- 每条指导必须人工审核
- 中英内容同时存在才展示
- 无审核内容时不显示空卡片
- App 内明确说明内容用于动作学习，不替代专业医疗或康复建议

## 10. 数据模型与状态设计

### 10.1 计划继续作为模板

`TrainingPlan` 和 `TrainingPlanItem` 继续保存计划定义：

```text
TrainingPlan
├── id
├── name
├── createdAt
├── updatedAt
└── items[]

TrainingPlanItem
├── id
├── exerciseId
├── defaultSets
├── defaultReps
├── defaultRestSeconds
└── order
```

`setStatesRaw` 与 `completedAt` 是 v1 的临时执行状态。v2 UI 不再写入它们；迁移期保留字段以兼容旧数据库，后续版本再移除。

### 10.2 每次执行使用独立 Session

```text
WorkoutSession
├── id
├── sourcePlanId?
├── planNameSnapshot?
├── startedAt
├── endedAt?
├── statusRaw              // active, completed, abandoned
├── notes?
└── exercises[]

WorkoutExercise
├── id
├── exerciseId
├── exerciseNameZHSnapshot
├── exerciseNameENSnapshot
├── order
├── plannedSets
├── targetReps
├── restSeconds
├── isSkipped
├── session?
└── sets[]

SetLog
├── id
├── order
├── targetReps
├── actualReps
├── weightKg?
├── completedAt?
├── isWarmup
└── workoutExercise?
```

保存名称快照是为了保证未来动作数据更新后，历史仍能反映训练当时看到的名称。GIF、图片和完整步骤不复制到 SwiftData，历史详情仍通过 `exerciseId` 尝试关联当前 Bundle 数据。

### 10.3 运行时状态

新增 `ActiveWorkoutStore`（或 `WorkoutSessionStore`）负责：

- 创建、恢复和结束训练
- 当前动作/组导航
- 完成、撤销和编辑组
- 休息计时的目标结束时间
- 统计计算
- 所有 SwiftData 写入与错误处理

View 不直接拼装训练统计，也不直接处理跨模型保存。

### 10.4 持久化与恢复

- 每次完成或编辑组后立即保存
- App 进入后台前保存当前 Session
- 恢复时查询唯一 `active` Session
- 若数据库异常出现多个 active Session，保留最近开始的一条并将其余标为 abandoned，同时记录日志
- 休息计时只需保存 `restEndsAt` 或在运行时根据最近完成组重建；不按秒写数据库

### 10.5 v1 数据迁移

- 计划、最近浏览和计划项目必须原样保留；旧收藏表保留在 schema 中以确保升级安全，但不再出现在 v2 UI 中
- 新增模型采用显式 SwiftData schema/version 迁移
- v1 `setStatesRaw` / `completedAt` 不转换成训练历史，因为缺少可靠的训练开始时间、逐组时间和重量
- 迁移后不清空旧字段，只由 v2 UI 忽略，避免不可逆数据破坏
- 增加迁移测试：使用 v1 fixture 打开 v2 schema 后，计划数量、名称、动作顺序、组数和次数不变

## 11. 关键统计定义

- **训练时长**：`endedAt - startedAt`
- **计划组数**：Session 内所有 `SetLog` 数量，不含训练开始后删除的动作
- **完成组数**：`completedAt != nil` 的 SetLog 数量
- **总次数**：完成组的 `actualReps` 之和
- **总训练量（kg·reps）**：完成且存在重量的组的 `weightKg × actualReps` 之和
- **完成动作数**：至少有一个完成组且未标记跳过的 WorkoutExercise 数量

所有统计使用同一 `WorkoutMetrics` 纯函数实现，并由单元测试覆盖边界情况。

## 12. 视觉与交互方向

- 延续深空背景与玻璃卡，不新增高饱和“燃脂”视觉
- 训练模式减少装饰性背景动效，确保数字和按钮可读
- 重量、次数使用大号等宽数字
- 完成组按钮应适合单手点击，最小触控区域 44×44pt
- 当前组使用青绿色强调，未完成组保持低对比，已完成组同时使用图标与颜色
- 休息计时器不遮挡返回、结束或紧急退出操作
- 所有训练页面保持中文主信息、英文辅助信息

## 13. 无障碍与可靠性

- Dynamic Type 至 AX5，训练输入区域不得裁切
- VoiceOver 可读出“动作名、第几组、目标次数、实际次数、重量、是否完成”
- 不能只用颜色表示完成、跳过或计时状态
- 减弱动效时关闭数字跳变和背景动画
- 完成组、结束训练和删除历史均提供明确反馈
- 使用公制千克作为 v2.0 唯一重量单位；单位切换延后，避免转换和展示混乱
- SwiftData 保存失败必须向用户展示可恢复错误，不使用静默 `try?`

## 14. 性能要求

- 进入或恢复训练模式 < 300ms（不含首次 GIF 解码）
- 完成一组到 UI 更新 < 100ms
- 1000 次训练、每次 10 个动作、每个动作 5 组时，历史首屏加载 < 500ms
- 历史列表使用分页或 FetchLimit，不一次加载所有 SetLog
- 训练页只加载当前动作 GIF；离开当前动作后释放或复用播放器资源

## 15. v2 版本范围

### v2.0：训练闭环

- 计划模板与训练 Session 分离
- 训练首页与继续训练
- 计划训练和自由训练
- 逐组重量/次数记录
- 休息计时
- 后台恢复
- 完训摘要
- 训练历史与详情
- 数据迁移、测试、无障碍与性能验证

### v2.1：现场效率

- 拼音与别名搜索
- 搜索和筛选组合
- 替代动作
- 计划模板复制与自由训练另存为计划
- CSV 导出

### v2.2：指导增强

- 经人工审核的关键提示和常见错误
- 指导数据覆盖层和来源说明
- Widget / App Intents
- 轻量个人记录展示

## 16. 明确不做

- 账户、登录、CloudKit 或其他云同步
- 社区、评论、关注、排行榜、打卡激励
- 会员、课程、广告或付费墙
- AI 摄像头姿态识别
- 自动生成未经审核的训练或医疗建议
- HealthKit、卡路里估算和身体数据管理
- Apple Watch 完整客户端
- 跨计划的复杂周期化编排
- iPad、visionOS 和 macOS 适配
- App Store 公开发行

## 17. 发布门槛

v2.0 合并前必须满足：

- 所有 v1 版权测试继续通过
- v1 数据迁移 fixture 测试通过
- 训练状态机与统计纯函数测试通过
- 至少覆盖开始、恢复、完成、放弃四条 UI 流程
- iOS 18 与 iOS 26 模拟器验证 Liquid Glass 双路径
- VoiceOver、Dynamic Type、Reduce Motion 手工走查
- 真实设备完成至少 3 次完整训练试用
- README、AGENTS.md 和版本说明同步更新
